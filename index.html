E613，同一个冷启动引擎（生产 027 配置，parallel 1，无图片编码器），每条请求用 strata_tune.prefill_pipe 切换，每值前后都插一条"不设"对照，合成文本，中位数。两卡分层的读 prompt 是两段流水：分块太大时第二张卡空等，太小时每块固定开销变多。1536 让 8K–16K 都切成多块（+16% / +12% / +5%），但 4K 也被切成两块，慢 23%；3072 只在 8K（2×4096，+16%）和 12K（2×6144，+8%）改分块，4K / 16K / 32K 不动。真实文本终判同向：8K 1,145 → 1,327、12K 1,341 → 1,453、4K 1,026 → 1,017。没有一个值能既不切 4K 又切 16K：按引擎成本式把 R = 1–20,000 全算一遍，2,976–3,400 与 3072 方案完全相同（切出来的块都 ≥4,096）；更小的 R 先切 7K、6K、5K 成 <4,096 的小块，≤1,700 才切 16K 但也切 4K。成本式把每块固定开销当常数，实测块 <4,096 罚得重得多，所以更好的是给分块加下限，不是换数字。E617 测了上游 #3821 的 STRATA_PREFILL_PIPE_FLOOR=4096 配 1600（紫色，同一引擎每请求切换、两侧夹 3072 对照）：7K +8%（切成 4096 + 尾块，一块够大就赚）、12K +3%、14K +4%、16K +5%、20K +2%，4K / 8K 不变，真实文本同向，10-29 07:1x 上生产。空白 = 该值没测（32K 两者分块相同）。E613, one cold engine (the production 027 config, parallel 1, no picture encoder), the value switched per request with strata_tune.prefill_pipe and an "off" control before and after every value, synthetic text, medians. On a layer split the prompt runs as a two-stage pipeline: chunks too big leave the second card waiting, too small pay a fixed cost per chunk. 1536 splits 8K–16K (+16% / +12% / +5%) but also cuts 4K in two, 23% slower; 3072 re-chunks only 8K (2×4096, +16%) and 12K (2×6144, +8%) and leaves 4K / 16K / 32K alone. The real-text check agrees: 8K 1,145 → 1,327, 12K 1,341 → 1,453, 4K 1,026 → 1,017. No value splits 16K without also splitting 4K: running the engine's cost formula for R = 1–20,000, everything from 2,976 to 3,400 gives the same plan as 3072 (all chunks ≥4,096); smaller values first cut 7K, 6K, 5K into chunks under 4,096, and only ≤1,700 splits 16K, together with 4K. The formula charges each chunk a constant cost while chunks under 4,096 cost far more here, so the better fix is a chunk floor, not another number. E617 measured upstream #3821's STRATA_PREFILL_PIPE_FLOOR=4096 with 1600 (purple; same engine, switched per request, 3072 controls on both sides): 7K +8% (cut into 4096 plus a tail: one big chunk is enough to win), 12K +3%, 14K +4%, 16K +5%, 20K +2%, 4K / 8K unchanged, real text agrees; in production since 10-29 07:1x. A gap = not measured (at 32K the two plans are the same).

已经到底的方向（别再试）Closed directions (do not retry)

  • 解码的配置级旋钮单独调都到头了：--kv-resident 缩小（E382，专家槽只 +0.7%）、单开 --pipeline-windows 2（E384，+1–6%）、--spec × --spec-min-p 16 点网格（E385，pipeline-windows 1 下 4/0.5 是峰值）。但组合有效：spec 3 / min-p 0.7 + pipeline-windows 2 解码 +10–16%（E387，三轮确认，10-09 上生产）。
  • 并发批槽（10-08 的结论，10-15 推翻）：当时常驻专家 41% 低于上游门槛、槽里不带 MTP；加上槽位草稿、单路保留流水窗口和后来的 #2985 后，两路并发已是生产（parallel 2）。
  • IQ3_S 的 MMQ 分块 / stream-K（E279/E280）、--prefill chunk 8192 即甜点（E296）、张量并行（E234，+6%）。
  • 上游自己测过对小卡无益：GDN 分块（需 128 SM）、Foresight 交换槽（解码变慢）、STAGE_PIN（IQ3_S 损坏，改回 opt-in）。
  • 0.1.42 的 opt-in（E413）和把 llama.cpp MMQ 补丁带进 Strata（E414）：只有 STRATA_SPLIT_MTP_BATCH=1 过线；TAIL_SKIP / ROUTE_RESIDENT / aux-cpus 在噪声内或更慢，RESIDENT_SORT / PF_FUSED 本机不触发；ggml 补丁在 Strata 的专家 GEMM 上 ±1%。
  • prompt 专家段（E450–E452）：llama.cpp 的 MMQ 在真实形状上 28–34 TOPS 封顶；换 tile 宽度不省时；原地读不搬运只 +0.5%。上游 0.1.43.1（E432）对本机无收益。
  • 还有空间的（10-20）：PCIe 拓扑不换——"x16+x4 大 prompt 约 1.5×"在 10-15 推翻：Strata 上长 prompt 等 PCIe 只占 0.2–0.7%，x8≈x16；<2K 的短 prompt 才有 43–54% 在等（E482，已由 STREAM_MIN 与 CPU 分担缓解）。解码：专家缓存命中 85% 已高于全知静态集，预测换入没有空间，杠杆是每窗换入量（E499，未测）。
  • Decode configuration knobs, each alone, are at their limit: shrinking --kv-resident (E382, expert slots only +0.7%), --pipeline-windows 2 alone (E384, +1–6%), a 16-point --spec × --spec-min-p grid (E385, 4/0.5 is the peak at pipeline-windows 1). The combination works: spec 3 / min-p 0.7 + pipeline-windows 2 decodes +10–16% (E387, three confirmation rounds, production since 10-09).
  • Concurrent batch slots (the 10-08 verdict, overturned 10-15): resident experts were 41%, below upstream's gate, and slots carried no MTP; with slot drafts, the solo path keeping its pipeline windows and later #2985, two parallel slots are production (parallel 2).
  • MMQ tiling / stream-K for IQ3_S (E279/E280), --prefill chunk 8192 is the sweet spot (E296), tensor parallel (E234, +6%).
  • Measured by upstream as no help on small cards: chunked GDN (needs 128 SMs), Foresight swap slots (slower decode), STAGE_PIN (broke IQ3_S, back to opt-in).
  • The 0.1.42 opt-ins (E413) and the llama.cpp MMQ patches inside Strata (E414): only STRATA_SPLIT_MTP_BATCH=1 passed; TAIL_SKIP / ROUTE_RESIDENT / aux-cpus within noise or slower, RESIDENT_SORT / PF_FUSED never trigger here; the ggml patches ±1% on Strata's expert GEMMs.
  • Prompt experts (E450–E452): llama.cpp's MMQ tops out at 28–34 TOPS on the real shapes; another tile width saves nothing; reading in place instead of gathering only +0.5%. Upstream 0.1.43.1 (E432) brought nothing here.
  • Where room is left (10-20): keep the PCIe topology — "x16+x4 reads big prompts ~1.5× faster" was overturned on 10-15: on Strata a long prompt waits on PCIe only 0.2–0.7% of the time, x8 ≈ x16; prompts under 2K wait 43–54% (E482, eased by STREAM_MIN and the CPU share). Decode: the expert cache already hits 85%, above an all-knowing static set; prediction has no room, the lever is swaps per window (E499, untested).
